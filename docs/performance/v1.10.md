# LlarTV v1.10 performance (reference TV, paired)

**Status: inside every paired allowance; the APK is over its +5% budget, which is accepted and explained below.**
v1.10 adds the weather city (#110: a settings row, an Open-Meteo search, an automatic choice and a cache that
records its place) and ships the Almali app icon and TV banner (#109). The reference-TV pair is the release gate
(see [the targets](baseline-v1.0.md#targets)).

## Setup

- Target: the reference TV, Xiaomi MiTV-MSSP3, Android 11/API30, with the owner's go-ahead and the owner's own
  configuration (342 bytes, SHA-256 `5b03e51b…`), checked byte for byte after every install and at the end.
- Baseline: [published v1.9 APK](https://github.com/almali-dev/almali-llartv/releases/download/v1.9/LlarTV.apk),
  739,322 bytes, SHA-256 `b1a394f554d11ef2a78fcec7a3438b3936aa6ac778894e3e433f0700253320ec` (downloaded again from
  the release: byte-identical).
- Candidate: the debug (minified) APK built from `main` `6939984` in a clean detached worktree, 786,186 bytes,
  SHA-256 `0a38ea6ce46d91a14e9211663ca2d3f5900ceb9073264c28d1e4be68a687efa2`. Same signing certificate, installed in
  place with `install -r -d`. The released APK differs only in its version (`versionCode 11`, `1.10`).
- Procedure, unchanged since v1.6: `scripts/measure.sh --serial <tv> --apk <apk> --runs 7` (one discarded warm-up,
  seven cold starts, seven returns from another app, three PSS samples) after a 20 s settle following each install,
  five pairs in an order-balanced sequence: v1.10 first, v1.9 first, v1.10 first, v1.9 first, v1.10 first
  (2026-11-07, 21:28–21:40).

### The cold start

Three of v1.10's five rounds (b, c, d: 1,113–1,114 ms) are the same as v1.9's fast rounds (1,098–1,133 ms). The
difference comes from two rounds: v1.10 a (1,242–1,690 ms), the first round, right after the first install of the
session, and v1.10 e (1,313–1,387 ms), whose seven samples all sit in the slower cluster the TV has shown since
v1.6, as v1.9 c did in four of its samples (1,296–1,356 ms). The pooled medians, which a single slow round moves
much less, differ by 20 ms, inside the roughly 30 ms of run-to-run noise. Nothing on the start path changed: the
weather place is resolved when the morning panel refreshes, after the first frame, and `TvLocation` is only read
with `location_auto=on` (off on this TV). One v1.10 c sample is 531 ms, below the fastest of the other 69 (1,084 ms),
so it is a measurement artifact; it does not move that round's median.

### The RAM reading

Both versions measure about 58 MB today, 7 MB above the 51,070 KB the minified build measured on 2026-11-04, so
today both are above the absolute TV limit of [the v1.9 rebaseline](baseline-v1.0.md#rebaseline-for-the-minified-build-v19)
(55,166 KB). The published v1.9 itself is over it, so the rise comes from the TV's state on the day, not from
v1.10, and the paired comparison, which shares that state, is the gate. The first sample of v1.9 e and of v1.10 d
(73,800 and 73,122 KB) is taken during a wallpaper decode; neither moves its round median.

### The APK size

The candidate is 46,864 bytes larger than v1.9, over the +5% budget (≤ 776,288 bytes) by 9,898 bytes. Entry by
entry against the published v1.9:

| Entry | Bytes (compressed) | From |
| --- | --- | --- |
| Ten launcher PNGs, the adaptive icon XML and `drawable-xhdpi/banner.png` | about +30,750 | The Almali app icon and TV banner (#109) |
| `classes.dex` | +10,612 | The weather city (#110) |
| `resources.arsc` | +3,592 | The strings of both |
| `AndroidManifest.xml` | +24 | The icon and banner attributes |

Without the brand assets the APK would be about 755 KB (+2.2%), inside the budget. The budget rule anticipates
this case: a new asset can exceed it on its own, and it is investigated and justified in its release, not hidden
by moving the baseline. The owner accepted it as it is (2026-11-07). The baseline stays at 739,322 bytes. One
saving remains open for a later release: the five legacy `mipmap-*/ic_launcher.png` (about 11 KB) are never used on
minSdk 28, where the adaptive icon always applies.

## Device checks before the release

- **Emulator** (`tv11`, Android 11): `scripts/install.sh emulator-5554 --apk <candidate>` installed in place (the APK
  pulled back is byte-identical, `home.conf` unchanged, LlarTV is Home and `.BingDream` the screensaver);
  `scripts/config.sh` wrote `clock=24 location_auto=on`, `--show` listed them, Home showed a 24 h clock, and empty
  values restored the file byte for byte; Somnambulator started the screensaver with the photo, its caption and the
  weather line. No LlarTV crash entry.
- **Reference TV**: the weather city was checked on the TV before its merge (search, the saved keys, the card, the
  automatic fallback with the TV's location off); the published release is installed with `scripts/install.sh` and
  checked again after publishing.
